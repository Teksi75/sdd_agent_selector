# feat(ui): critique v2 final polish — 8 items cerrados

Cierra los 8 items pendientes del backlog del critique v2 (Nielsen 28/40 → 36/40 estimado) en un solo PR.

## Qué cambia

### P0-1 (2da mitad) — copy de onboarding en el hero

Antes: el hero solo tenía el título + un lede párrafo. Un usuario que aterriza por primera vez no sabía que arriba había 5 estrategias clickables y que los 18 cards de abajo se actualizaban.

Ahora: `<p id="hero-onboarding-hint">` agregado al hero con el copy:
> Arriba hay 5 estrategias prearmadas (Balanceado ya está activa). Hacé click en cualquiera y los 18 cards de abajo se actualizan con la asignación nueva. Después exportá y pegá en `gentle-ai/agents/`.

El hint se oculta automáticamente cuando el user clickea cualquier `button[data-config-key]`. El pre-select silencioso NO la oculta (el listener vive en `config-mount`, no en `onSelect` — son paths distintos).

### P1-1 — tier h2 visibility

Antes: `text-[11px] text-slate-400` (≈8.5px efectivo, contraste 4.6:1 — al borde de AA). Casi invisibles al cargar.

Ahora:
- `text-sm` (14px) + `text-slate-200`/`text-slate-300`/`text-indigo-300` (contraste 7-11.5:1)
- `border-b border-slate-800/60 pb-2` para separación visual entre tiers

### P1-2 — SOFT badge color

Antes: `text-amber-300` (overloaded con el color de warning "Sin modelo elegible" → el soft-fallback se leía como error).

Ahora: `.soft-badge` con color `#d8b4fe` (purple-300) + prefijo `~` via `::before`. Color-blind safe (la forma lleva el significado, no solo el color).

Aplicado en `cli-mirror-table.js` y `justification-ui.js`.

### P2-1 — refresh affordance

Antes: `.freshness-refresh` era `text-xs px-2.5 py-1` (~28px tall). Fácil de pasar por alto en el hero.

Ahora: `min-height: 2.25rem` + `font-size: .8125rem` (text-sm) + `padding: .4rem .75rem`. El botón se siente como una acción real, no como un link secundario.

### P2-4 — aria-live per-card

`aria-live="polite"` en el grid de cards de `justification-ui.js`. Los screen readers anuncian el nuevo assignment set después de un `selectConfig`. `polite` (no `assertive`) porque el cambio es informativo, no un alert crítico.

### P2-5 — export menu descriptions

Antes: cada item del export menu solo tenía el label (`Copiar` / `Descargar`). El usuario no sabía qué se exportaba sin hacer click.

Ahora: `formatRowHtml` acepta `format.description` opcional. Cuando está presente, emite un `<span class="export-menu-desc">` debajo del label con color muted (#64748b) y font-size 10px.

Aplicado en los 4 lugares (cli-mirror, justification, composite-chart, ref-table). Backward-compat: cuando `description` falta, el render es idéntico al anterior.

### P2-6 — rename "CLI mirror" → "Equivalentes CLI"

Antes: el nombre "CLI mirror" no comunicaba qué hace la tabla. La sección era invisiblemente accesible solo como `aria-label="CLI mirror: 18 agentes"`.

Ahora:
- `aria-label="Equivalentes CLI: 18 agentes"`
- Nuevo `<h3 data-test="cli-mirror-title">Equivalentes CLI</h3>` visible en el header, al lado del counter "N/18 con modelo"

### P2 eficiencia — keyboard shortcuts

Nuevo módulo `js/components/keyboard-shortcuts.js` + help overlay HTML estático al final del body.

| Shortcut | Acción |
|----------|--------|
| `?` | Toggle help overlay |
| `g` + `i` | Jump a #tier-1 (Acción → resultado) |
| `g` + `j` | Jump a #tier-2 (Datos de soporte) |
| `g` + `k` | Jump a #tier-3 (Catálogo completo) |
| `r` | Click en el refresh button |
| `Esc` | Close help overlay (o dropdown de export) |

Los keystrokes se ignoran cuando el focus está en un text-entry (input, textarea, select, contenteditable) — el `g` de "google" no salta a tier-1.

El prefix `g` tiene un timeout de 1.2s. Si el user no completa la secuencia a tiempo, el prefix se descarta.

## Decisiones / tradeoffs

**Todo en 1 PR vs. 8 PRs chicos:** el critique v2 ya da el plan de 8 items atómicamente separados, pero 8 PRs con 1-3 tests cada uno es overhead de CI + review + squash-merge. Un PR de ~300 líneas + 24 tests es más manejable y mantiene la trazabilidad (cada test nombra el item del critique que pinnea).

**Shortcut `r` sin `g` prefix:** el critique sugería `g+i/j/k` para tier jumping (vim-style, evita colisiones con typeo de texto), pero `r` para refresh se usa sin prefix porque el botón de refresh es chico y el keystroke es el mismo que el usuario ya asocia con "recargar" (Ctrl+R sin Ctrl). La colisión con la letra `r` en un text-entry ya está cubierta por el guard `isTextEntry`.

**`aria-live="polite"` en el grid entero, no per-card:** ponerlo per-card haría que el SR lea 18 cards en cada click. A nivel grid, el SR lee solo los cambios si el contenido del mismo `<div>` cambia (jsdom vs browser real varía — en browsers modernos con `aria-atomic="false"`, solo se leen los nodos modificados).

**SOFT badge color: purple, no green ni blue:** purple se sentía más "best-effort" / "approx" que emerald (que es el color del tier high) o indigo (que es el tier balanced). El significado "no es 100% ideal" se alinea mejor con purple.
