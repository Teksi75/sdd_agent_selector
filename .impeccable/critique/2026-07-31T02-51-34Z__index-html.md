# SDD Agent Selector V4 — Critique Snapshot (2026-07-30)

Operate mode (tool/dashboard). Target: `index.html` (the page source) + all `js/components/*` and `js/services/*`. Live cross-check vs `https://teksi75.github.io/sdd_agent_selector/` — exact byte match with `dist/index.html`.

## Headline

The data layer is bespoke and rich (24 models, 9 SDD phases, 18 agents, 5 strategy presets, BenchLM provenance). The **page chrome is generic and under-instrumented**. Strengths live in the data semantics; weaknesses live in how the data is presented and what the user can DO with it.

## Strengths (keep these)

- **Tier system is consistent across all 7 data surfaces** (high=emerald, balanced=indigo, budget=amber, reference=rose). One mental model carries the user through 8 sections.
- **Justification cards are a "show your work" audit trail** — every assignment shows the score check + cost check + alternatives, with the actual operands. A teacher who trusts benchmarks can verify the choice from the page itself.
- **Fail-soft contract is real** — every error path renders something visible (— unavailable —, Sin modelo elegible, amber soft-fallback card, stale-data banner). The page never crashes or blanks.

## The 3 P0 blockers (must fix)

| # | Issue | Source | What it breaks |
|---|---|---|---|

No plain-language explainer of what SDD is, what the 9 phases / 18 agents are, what `tier` / `lifecycle` / `BenchLM` mean, or what the user is *supposed to do* on this page. | A persona, P0 issue | Every first-time visit costs ~30s of orientation. The stated persona (a teacher) is not a developer. |

The single interactive thing (5 config buttons) sits in a card visually identical to every read-only chart. | A P0 issue | Discovery problem. The user CANNOT complete the workflow the page is built for. |

## Top 8 P1s (high leverage)

1. **No legend for tier colors, reliability dots, or verified/estimated badges** — interpretation is locked behind code-reading
2. **Config selection has zero in-page feedback** — no toast, no scroll-to-impact, no "applied" indicator (peak-end failure on the page's most important interaction)
3. **Tier label asymmetry** — data model says `high/budget`, UI shows `max/min` in 3 of 7 surfaces. The word `min` does double duty (min-cost preset AND budget tier)
4. **Touch targets on config-selector buttons are ~24px tall, below WCAG 2.5.8** — only interactive primitive on the page
5. **`prefers-reduced-motion` not honored** while 4 transition rules ship (incl. `transition: width` on every chart bar = 18 layout reflows per render)
6. **No `:focus-visible` anywhere** — keyboard focus invisible on the dark surface
7. **Real contrast failure on tier-tag chips** — `text-slate-500` on `bg-rose-500/80` is **1.12:1**, on `bg-amber-500/80` is **1.46:1** (the visible "min"/"reference" labels are unreadable)
8. **5 config buttons don't wrap on narrow viewports** — overflow / truncate on 360px phones

## Provocative question for the user

> If the page's purpose is to view curated LLM data and then export it to `gentle-ai`, **where is the export?** If it's missing, that's the single largest design gap between stated intent and delivered UI.

## Triage (suggested order)

The 3 P0s are the floor. Tackling them in order:
1. **Export action first** (P0-3) — closes the loop on the actual use case
2. **Visual hierarchy + framing** (P0-2 + P0-1) — one re-flow of the page, biggest single change
3. **Then P1s as budget allows** — start with tier-label asymmetry, contrast, and motion/focus (cheap, high-yield)

## Open for user choice

The user should pick which 1-3 of the above to address in the next PR. Each is a self-contained chunk; the user can sequence.
